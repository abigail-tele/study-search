# CLAUDE.md — Cancer Trials Plain-Language Finder

Congressional App Challenge entry. Deadline: confirm district date (common date Mon Oct 26, 2026). Target: submittable by Sun Oct 25 night.
Full plan with schedule and acceptance criteria: `docs/PLAN.md`. Read it at the start of every session.

## What we are building
A web app for patients and families. User searches by cancer type in plain words → ranked cancer trials come back as citation cards linking to ClinicalTrials.gov → user picks one → our fine-tuned small model gives a plain-language summary.

## Hard rules (never break)
1. **Cancer only.** Index only oncology trials. Off-topic queries return `off_topic: true` + cancer chips. Never search the whole index for them.
2. **Model rewrites free text only** (brief summary, eligibility). Title, status, phase, ages, sex, sites, sponsor, dates, NCT ID always come straight from stored API data.
3. **Faithfulness check on every model output.** Any number, age, unit, drug, gene/marker, or stage term in the output must appear in the source. Miss → return glossary-swapped original, set `fallback_used: true`, log it.
4. **No live ClinicalTrials.gov calls during user requests.** Live server reads SQLite + FAISS only.
5. **Licenses: permissive only** (MIT, Apache 2.0, BSD, public domain). No GPL code, no Cochrane data, no training data generated by commercial chatbots, no copying existing summarizer repos.
6. **Log every dependency in `CREDITS.md` and every AI-assisted task in `AI_USE.md` the same session** (what, which model/agent, which files). The challenge requires full AI disclosure.
7. **No medical advice wording.** Every summary panel shows "For education, not medical advice."
8. **Never store user queries or ZIPs** beyond the request.

## Architecture
```
OFFLINE (scripts, run once + nightly)
  ClinicalTrials.gov v2 API → indexer.py → SQLite (trials, trial_cancer_types, locations, fts, summaries)
  SQLite → embed.py (all-MiniLM-L6-v2) → FAISS flat IP index + row map
  cancer.gov PDQ pages → pdq_pairs.py (scrape + align) → train.py (flan-t5-base) → checkpoint
  checkpoint + SQLite → batch_summarize.py (+ faithfulness) → SQLite.summaries
ONLINE (FastAPI)
  /api/cancer-types  /api/search  /api/study/{nct}  /api/summary/{nct}
  search: detect cancer type → candidates by tag → FTS5 top50 + FAISS top50 → RRF (k=60) → filters (status, age, ZIP distance) → top 10
  summary: read SQLite.summaries; miss → live CPU generation + same check → store
```

## Stack
Python 3.11, FastAPI, uvicorn, sqlite3 (FTS5), faiss-cpu, sentence-transformers, transformers, datasets, torch, httpx, beautifulsoup4, textstat, pytest. Frontend: plain HTML/JS + fetch. Host: Hugging Face Spaces (Docker) or Render.

## Conventions
- Type hints, short functions, docstrings that explain WHY (team members must explain every part to judges).
- Every module gets a 3–5 sentence plain-English section in `docs/HOW_IT_WORKS.md`.
- Config values (thresholds, k, paths) live in `config.py`, never inline.
- Commit after each passing task: `git commit -m "<phase>: <what>"`.
- Tests with pytest; mock network calls; tiny fixture DB in `tests/fixtures/`.

## How to work (orchestration)
You are the orchestrator. Plan, delegate, verify. Keep your own context small.
- Delegate by default. Use the subagents in `.claude/agents/`:
  - `scout` (haiku) — read/search code, docs, API responses; answer factual questions in ≤15 lines.
  - `grunt` (haiku) — mechanical work: JSON data files, fixtures, mock responses, boilerplate, renames, README/CREDITS/AI_USE upkeep.
  - `test-runner` (haiku) — run tests/scripts, return only failures + 1-line cause each.
  - `data-engineer` (sonnet) — indexer, SQLite schema, embeddings, FAISS, search, geo.
  - `ml-engineer` (sonnet) — PDQ scraping/alignment, training script, summarizer, faithfulness check, eval.
  - `api-builder` (sonnet) — FastAPI app, frontend, deployment config.
  - `reviewer` (opus) — gate review at the end of each phase and for anything touching rules 1–3.
- Run independent subagents in parallel (e.g. data-engineer on indexer while ml-engineer builds PDQ scraper while grunt writes cancer_types.json).
- Give each subagent: the exact files it owns, the interface it must match, and the done-check. Ask for a ≤10-line report, not a transcript.
- Don't re-read files a subagent just reported on unless the report shows a problem.
- After each phase: test-runner → reviewer → fix → commit → update `AI_USE.md` (via grunt).
- If blocked on something only a human can do (portal registration, GPU training run, eligibility), stop and list it clearly.
